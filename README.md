# KhabarFori | خبرفوری

Persian RTL newsroom, public reading experience, enterprise API and Flutter mobile source.

## Requested delivery targets

**Android:** an installable Flutter APK. **iPhone/iPad:** the mobile web app at `/mobile`, with a home-screen manifest and standalone presentation. The desktop admin remains at `/`.

An APK has **not** been generated in this environment. Use the prepared `Build installable KhabarFori Android APK` workflow with a reachable production API. Review builds are explicitly debug-signed; release builds require your own protected signing key. Native iOS runners are no longer generated by the default bootstrap.

See [راهنمای اندروید و وب‌اپ آیفون](docs/MOBILE-DELIVERY-FA.md).

## What is included

- **Web:** React/TypeScript/Tailwind newsroom dashboard, news editor and publishing states, filters, CSV reports, public news and VIP previews, comments/reactions/bookmarks, employee directory, editorial messages, roles, subscription checkout, notifications and account forms.
- **Production admin:** `apps/admin` is a real Next.js application generated from the shared web source. It uses a server-side proxy with HttpOnly access/refresh cookies. Edit the root `app`, `components`, `lib` and `production/proxy.ts`; run `node scripts/prepare-next-admin.mjs` to synchronize.
- **Backend:** NestJS REST API, Prisma/PostgreSQL, bcrypt password hashing, JWT, refresh rotation, revocation, RBAC, DTO validation, rate limits, archive-on-delete, paid-entitlement checks, audited publishing/role changes, payment verification adapter, Supabase image uploads and Firebase notification service.
- **Mobile:** Flutter/Dart with Riverpod, a news domain/repository/presentation boundary, secure token storage, Persian localization, news/search/detail, subscriptions, opinions, comments, bookmarks, employees, editor contact, profiles and notifications.
- **Operations:** SQL migration, taxonomy/role/plan seeds, environment examples, Docker Compose, OpenAPI specification, CI, security unit tests and database integration test script.

## Two execution modes

The private Sites preview is a **review environment**. Sample content and analytics are labeled. News edits, bookmarks, comments, employee additions and messages persist in owner-scoped D1 records. It does not collect payments or create production accounts. Its preview schema is deliberately separate from the PostgreSQL production schema.

The production web application requires `KHABARFORI_API_URL`. All identity, content, permissions, subscriptions and organizational information then come from NestJS/PostgreSQL. The private preview does not deploy NestJS or a PostgreSQL server. Do not treat the preview as a production launch.

## Quick start: API and PostgreSQL

Requirements: Node.js 22+, Docker Compose v2. Mobile additionally requires Flutter, Android tooling. iOS uses the mobile web app.

1. Copy `backend/.env.example` to `backend/.env`. Set a random `JWT_SECRET`, a unique `ADMIN_PASSWORD` and your initial admin email. Example values must be replaced.
2. Set `POSTGRES_PASSWORD` in your shell, using a URL-safe value or URL-encode it in database URLs.
3. Run `docker compose up --build -d`.
4. Seed roles, categories, departments and plans: `docker compose exec api npm run db:seed`.
5. Open `http://localhost:3000`. Sign in from **حساب کاربری → ورود** with the configured admin identity.
6. Local API docs are at `http://localhost:4000/docs` when `ENABLE_API_DOCS=true`.

Set `SEED_DEMO=true` only in development to insert one explicitly labeled sample article and employee. Seeds do not reset existing passwords, payments or content.

## Run without containers

```bash
cd backend
npm ci
# Load your environment using your process manager or shell.
npm run db:migrate
npm run db:seed
npm run build
npm start
```

From the repository root:

```bash
npm ci
node scripts/prepare-next-admin.mjs
# Set KHABARFORI_API_URL=http://localhost:4000
npm --prefix apps/admin run dev
```

Production Next.js build: `npm --prefix apps/admin run build`, then `npm --prefix apps/admin start`. See `production/Dockerfile.admin` for a standalone container. The root `npm run build` builds the Cloudflare-compatible review deployment, not the NestJS backend.

## Mobile

```bash
cd mobile
bash bootstrap.sh
flutter run --dart-define=API_URL=https://YOUR_API/api/v1 --dart-define=PUBLIC_WEB_URL=https://YOUR_WEB
```

`bootstrap.sh` now generates the Android runner only and preserves the authored Dart application. No APK binary is included yet. iOS uses `/mobile` in Safari; see [mobile delivery](docs/MOBILE-DELIVERY-FA.md).

## Validation

```bash
cd backend
npm test
npm run build
# With an isolated PostgreSQL database and a running API:
node test/integration.mjs
```

The CI workflow provisions PostgreSQL, applies migrations, seeds roles, runs API tests, builds Next.js and analyzes/tests Flutter. It has been authored but has not been run on GitHub from this environment. Exact locally executed checks and limitations are in [TESTING.md](docs/TESTING.md).

## Release status

This is an implementation and deployment package, not a certified production system. Provider credentials, a real payment adapter, phone/email ownership verification, native builds/signing, database integration execution, load tests, distributed throttling, backups and an operational security review remain launch work. Some analytics are aggregate-only; full time-series reporting and a live social provider are not implemented. Millions-of-users capacity is an architecture target, not a measured claim.
