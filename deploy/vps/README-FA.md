# استقرار KhabarFori روی VPS

این بسته آماده اجراست، اما در این گفتگو روی سرور اجرا نشده است. اتصال مستقیم SSH از محیط ساخت با Network is unreachable متوقف شد. هیچ به‌روزرسانی سیستم، تغییر رمز یا فایروال روی سرور انجام نشده است.

## خروجی

- PostgreSQL 16 روی همین VPS، بدون اشتراک یا هزینه دیتابیس جداگانه؛ ظرفیت تابع منابع VPS است.
- پنل مدیریت Next.js در `https://YOUR_DOMAIN/` و وب‌اپ کاربران در `/mobile`.
- API عمومی در `https://YOUR_DOMAIN/api/v1` با بررسی مجوز سمت سرور.
- ورود مدیر با `admin` یا ایمیل انتخاب‌شده و رمز تعیین‌شده هنگام نصب.
- ثبت‌نام و ورود کاربر با شماره ایرانی `09…` یا `+98…` و رمز عبور؛ این روش اثبات مالکیت شماره با پیامک نیست. OTP پیامکی هنوز پیاده‌سازی نشده است.
- شماره با ارقام فارسی و عربی به همان حساب با قالب بین‌المللی تبدیل می‌شود.

## پیش‌نیاز واقعی

یک دامنه یا زیردامنه تحت کنترل خودتان با رکورد A به IP سرور لازم است. رکورد AAAA اشتباه را هم اصلاح کنید. سایت معرفی‌شده خبرفوری را فقط در صورت کنترل DNS آن استفاده کنید. پورت‌های 80 و 443 باید به این VPS برسند.

از کامپیوتر خودتان یا کنسول ارائه‌دهنده وارد شوید. رمز را در خط فرمان، فایل سورس یا گفتگو نگذارید. اگر SSH فقط publickey می‌پذیرد، از کنسول ارائه‌دهنده برای افزودن کلید عمومی خودتان استفاده کنید؛ نیازی به فعال کردن ورود root با رمز نیست.

پیش از نصب، سیستم‌عامل و سرویس‌های موجود را بررسی کنید:

```bash
cat /etc/os-release
free -h
df -h /
ss -lntp
```

این اسکریپت‌ها وب‌سرور قبلی را متوقف نمی‌کنند و فایروال یا SSH را بازنویسی نمی‌کنند. اگر پورت 80 یا 443 اشغال است، قبل از اجرا باید مسیر استفاده از وب‌سرور موجود مشخص شود.

Docker Engine و Compose plugin باید روی سیستم‌عامل پشتیبانی‌شده نصب باشند. برای Ubuntu از مخزن رسمی طبق https://docs.docker.com/engine/install/ubuntu/ استفاده کنید. پیش از ارتقای سیستم از داده‌های موجود snapshot بگیرید؛ ارتقای سیستم و نیاز به reboot باید با وضعیت سرویس‌های موجود هماهنگ شود.

فایروال: پورت واقعی SSH را قبل از فعال‌سازی فایروال باز نگه دارید، سپس TCP 80/443 را مجاز کنید. PostgreSQL، API و Next.js در compose این بسته هیچ پورتی روی میزبان منتشر نمی‌کنند. قواعد فایروال Docker را هم در نظر بگیرید؛ صرفاً UFW برای پورت‌های منتشرشده Docker کافی نیست.

## انتقال و اجرا

بسته اصلاحات را در ریشه سورس فعلی استخراج کنید و تغییرات را به مخزن خودتان بفرستید. فایل CI موجود شما در این بسته جایگزین نمی‌شود.

سورس را با دسترسی GitHub خودتان روی VPS دریافت کنید یا پوشه پروژه را با SCP منتقل کنید؛ دانلود ZIP خصوصی GitHub بدون احراز هویت کار نمی‌کند. همه فرمان‌های زیر در ریشه پروژه اجرا می‌شوند.

```bash
python3 deploy/vps/configure.py
bash deploy/vps/start.sh
```

پیکربندی دامنه، ایمیل مدیر و رمز جدید مخصوص برنامه را می‌پرسد. رمز مدیر 16 تا 72 کاراکتر است. رمز PostgreSQL و کلید JWT تصادفی تولید می‌شوند. فایل `.env.vps` با دسترسی 600 ذخیره می‌شود؛ آن را در Git قرار ندهید. نام ورود `admin` به حساب ایمیل همین تنظیمات متصل است.

فرمان start ساخت تصاویر، مهاجرت دیتابیس و seed حساب مدیر را اجرا می‌کند. داده‌های نمایشی وارد نمی‌شوند؛ اولین خبر واقعی را مدیر باید ایجاد و منتشر کند. اجرای دوباره، رمز مدیر موجود را عوض نمی‌کند. برای عوض کردن رمز از پنل استفاده کنید و `.env.vps` را به‌عنوان روش reset حساب ویرایش نکنید.

Caddy با دامنه قابل دسترس گواهی HTTPS می‌گیرد. مستند رسمی: https://caddyserver.com/docs/automatic-https

## بررسی راه‌اندازی

```bash
docker compose --env-file .env.vps -f compose.vps.yaml ps
docker compose --env-file .env.vps -f compose.vps.yaml logs --tail=80 api admin gateway
```

سپس `https://YOUR_DOMAIN/api/v1/health` باید وضعیت `ok` و service برابر KhabarFori برگرداند. دامنه نمونه را با دامنه واقعی جایگزین کنید. پنل را باز کنید، با admin وارد شوید، خبر بسازید و منتشر کنید؛ بعد در مرورگر دیگری ثبت‌نام با شماره و رمز و مشاهده خبر را بررسی کنید. موفقیت این مراحل روی VPS هنوز تأیید نشده است.

## اتصال APK واقعی

پس از فعال شدن HTTPS و API، گردش کار `Build installable KhabarFori Android APK` را در Actions اجرا کنید:

- api_url: `https://YOUR_DOMAIN/api/v1`
- web_url: `https://YOUR_DOMAIN`
- build_mode: `review` برای نصب آزمایشی، یا release همراه کلید امضای خودتان.

APK قبلی به شبیه‌ساز اشاره می‌کند و خودکار آدرسش تغییر نمی‌کند؛ باید دوباره ساخته شود. برای نسخه‌های منتشرشده کلید امضا باید ثابت باشد. اگر APK آزمایشی جدید به علت تفاوت امضای debug روی قبلی نصب نشد، حذف نسخه آزمایشی قبلی داده‌های محلی آن را پاک می‌کند.

## نسخه پشتیبان

```bash
bash deploy/vps/backup.sh
```

خروجی در `backups` ایجاد می‌شود. آن را با دسترسی محدود به محل دیگری هم منتقل کنید؛ بکاپ فقط روی همان VPS، خرابی کامل سرور را پوشش نمی‌دهد. زمان‌بندی و آزمون بازیابی هنوز انجام نشده‌اند. برای بازیابی ابتدا روی دیتابیس مجزا از `pg_restore` استفاده کنید. هرگز `docker compose down -v` را برای به‌روزرسانی اجرا نکنید؛ حجم دیتابیس را حذف می‌کند.

## قابلیت‌های نیازمند سرویس بیرونی

- SMS/OTP، بازیابی رمز، درگاه پرداخت، Supabase Storage و FCM بدون اتصال و تنظیمات واقعی فعال نیستند. این بسته ادعای فعال کردن آن‌ها را ندارد.
- ورود فعلی شماره + رمز است. ثبت‌نام با شماره به معنی تأیید مالکیت آن نیست.
- برای تکمیل موارد بالا باید سرویس‌های واقعی انتخاب و پیکربندی شوند. PostgreSQL این بسته مستقل از Supabase است.
- رمز root را از کنسول امن با `passwd` تغییر دهید و از رمز برنامه جدا نگه دارید؛ رمزهای ارسال‌شده در گفتگو در بسته ذخیره نشده‌اند.
